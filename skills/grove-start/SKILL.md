# grove-start — 작업 착수

워크스페이스 루트의 계획 세션에서 실행. 워크트리를 세우고 계획 단계 화면까지 열어줌

## 원칙

**멈춤 지점이 두 곳 있음. 거기서는 반드시 사용자 답을 기다림.**

| 단계 | 누가 정하나 |
|---|---|
레포 특정 | 사용자가 알면 사용자, 모르면 내가 탐색해서 후보 제시 |
**작업명** | **항상 사용자.** 나는 후보만 냄 |
prefix·PLAN 초안·화면 배치 | 내가 함 |

---

## 1. 성격 판단

사용자 설명에서 운영 급한 건인지 판단

- 장애·데이터 오류·즉시 배포 뉘앙스 → `--hotfix` 를 쓸지 **한 줄로 확인**
- 그 외 → 기본 `feature`

## 2. 레포 특정 — 먼저 물어봄

**탐색부터 하지 말 것.** 사용자가 이미 아는 경우가 6~7할임. 먼저 이렇게 물음:

> 건드릴 레포 중에 이미 아는 것 있음? 있으면 그것부터 잡고, 계약 상대만 제가 찾겠음

### 알고 있다고 하면
그 레포를 확정하고, **계약 상대만** 보강 탐색:
- 서버 레포면 → 그 API 를 소비하는 BFF·배치·앱이 있는지
- 스키마·이벤트를 바꾸면 → 같은 테이블·토픽을 읽는 레포

### 모른다고 하면
`gh` 를 1순위로 씀. org 3곳을 훑음:

```bash
gh search code "<핵심 식별자>" --owner <org> --limit 20
```

org 가 여럿이면 각각 돌릴 것.

키워드는 사용자 표현이 아니라 **코드에 있을 법한 식별자**로 바꿔서 검색 (함수명·엔드포인트 경로·enum 값·테이블명·에러 메시지).

로컬 보강이 필요하면:
```bash
grep -rl "<식별자>" "$(grove repos >/dev/null && echo ~/Projects/repos)" | head -20
```

GROVE_REPOS 아래에 없는 레포가 나오면 먼저 clone:
```bash
gh repo clone <org>/<repo> <GROVE_REPOS 경로>/<repo>
```

찾은 결과는 **레포별로 왜 걸리는지 한 줄씩** 붙여서 제시. 목록만 던지지 말 것

## 3. 작업명 — 후보를 내고 멈춤

규칙: 짧은 영문 케밥, prefix 없음(브랜치 템플릿이 알아서 붙임), 기존 워크트리와 중복 없음

```bash
grove ls                         # 중복 확인
```

후보 **3개**를 성격을 달리해서 제시:

| 축 | 예 |
|---|---|
기능 중심 | `guest-checkout` |
문제 중심 | `checkout-drop-fix` |
짧은 축약 | `guest-co` |

제시하고 **사용자 선택을 기다림.** 임의로 진행하지 말 것

## 4. 워크트리 생성

```bash
grove new [--type <종류>] <선택된 이름> <repo>...
```

종류는 기본 `feature`. 핫픽스는 `--hotfix` (= `--type hotfix`), 그 밖에 `grove types` 로 확인. 브랜치는 `GROVE_BRANCH` 템플릿을 따름

레포별 base 브랜치가 다르면 `grove new` 로 주 레포만 만들고 나머지는 `grove add --base <브랜치>`.

## 5. PLAN.md 초안

워크트리 루트의 `PLAN.md` 를 채움. **해결책이 아니라 문제 정의까지만.**

```markdown
# <작업 제목>

## 목표
- 무엇을 왜 바꾸는지 한두 줄

## 계약            ← 레포가 둘 이상이면 필수
- API·이벤트·스키마 중 레포 사이를 오가는 것. 시그니처·필드명까지 확정
- 여기가 바뀌면 모든 실행 세션에 통지해야 함

## 관련 파일
- repo-a: path/to/File.kt — 왜 여기가 걸리는지
- repo-b: path/to/handler.ts — 왜

## 체크리스트
- [ ] repo-a: 무엇
- [ ] repo-b: 무엇

## 미해결 질문
- 계획 단계에서 못 정한 것

## 결정 로그
- YYYY-MM-DD: 결정 — 대안 — 이유
```

**하지 않을 것**: 수정 방향 제시, 코드 스니펫 수준 분석, "변경 불필요" 판단. 그건 실행 세션 몫임

## 6. 화면 열기

```bash
grove open <작업명>
```

계획 세션이 `<작업명>-plan` 이름으로 뜨고 레포 원본 읽기 권한을 가짐. PLAN.md 를 채운 뒤 실행 단계로:

```bash
grove open <작업명> --exec
```

## 7. 마무리 안내

한 줄로 다음 행동을 알려줌:

> `<작업명>` 워크트리 준비됨. 계획 페인에서 PLAN.md 를 확정한 뒤 `grove open <작업명> --exec` 로 레포별 세션을 띄우면 됨

- 워크스페이스 규칙 → 워크스페이스 루트의 `CLAUDE.md`

- 작업 종료 → `grove rm <작업명>` (아카이브 + 회고 draft 생성)
