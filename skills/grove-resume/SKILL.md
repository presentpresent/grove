# grove-resume — 작업 복귀

며칠 전 grove 로 돌아올 때, **사람이 PLAN.md 를 처음부터 다시 읽지 않아도 되게** 상태를 복원함.

## 0. 어느 grove 인지 정함

작업명이 주어졌으면 그대로 씀. 아니면 목록에서 고르게 함:

```bash
grove ls
```

애매하면 최근 손댄 순으로 후보를 좁힘:

```bash
grove ls
```

여러 개면 **묻고 멈춤.** 임의로 고르지 말 것

## 1. 문서에서 복원

`<grove>/PLAN.md` 를 읽고 아래를 뽑음:

| 뽑을 것 | 어디 |
|---|---|
남은 일 | 체크리스트의 미완료 항목 |
왜 이렇게 정했나 | 결정 로그 |
**막혀 있던 것** | 미해결 질문 |
계약 | `## 계약` 절 — 실행 세션들이 지켜야 할 것 |

`MERGE_REQUESTS.md` 도 읽어 PR 진행 상태를 봄

## 2. 코드에서 복원

문서는 사람이 갱신을 빠뜨림. **코드가 진실임.** 레포마다:

```bash
git -C <grove>/<repo> branch --show-current
git -C <grove>/<repo> status --short
git -C <grove>/<repo> log --oneline origin/HEAD..HEAD 2>/dev/null | head -20
```

PR 상태는 실제로 조회:

```bash
gh pr list --repo <org>/<repo> --head <브랜치> --json number,state,title,url
```

## 3. 문서와 코드의 차이를 짚음

여기가 이 스킬의 핵심임. 둘이 어긋난 곳을 **먼저** 보고함:

- 체크리스트는 미완료인데 커밋은 이미 있음 → 체크만 안 한 것인지 확인 필요
- 체크는 됐는데 커밋이 없음 → 작업이 날아갔거나 다른 브랜치에 있음
- PR 이 머지됐는데 MERGE_REQUESTS.md 는 open → 문서 갱신 필요
- 커밋되지 않은 변경이 남아 있음 → 어디까지 하다 멈췄는지의 단서

## 4. 요약해서 보고

이 형식으로 짧게:

```
<작업명> — 마지막 손댄 지 N일

진행:  repo-a ✅ 커밋 3개 · PR #123 merged
       repo-b ⏳ 커밋 1개 · PR 없음
       repo-c ⬜ 변경 없음

막힌 곳:  <미해결 질문에서>

어긋남:  <문서 vs 코드 차이. 없으면 생략>

다음 한 수:  <체크리스트 첫 미완료 항목>
```

## 5. 화면 되살림 — 둘 중 하나를 **골라서** 실행

나란히 제시하지 말고 아래 기준으로 판단한 뒤 하나만 돌릴 것

| 상황 | 명령 |
|---|---|
계약(`## 계약`)이 아직 비었거나 미해결 질문이 남음 | `grove open <작업명>` |
**계약이 확정돼 있고 체크리스트에 남은 구현이 있음** | `grove open <작업명> --exec` |

```bash
grove open <작업명> --exec
```

**`--exec` 없이 열면 페인만 깔리고 에이전트는 안 뜸.** 그 상태에서 사람이 페인마다
`claude` 를 직접 치면 세션 이름도 계약 프롬프트도 없는 세션이 됨 — 자기가 무슨
레포를 맡았는지 모르는 채로 시작함

`--exec` 이 레포마다 해주는 것:
- 세션 이름을 `<작업명>-<레포명>` 으로 박음
- "너는 이 레포만 담당한다, PLAN.md 를 먼저 읽어라" 계약 프롬프트 주입

herdr 워크스페이스가 이미 살아 있으면 새로 만들지 않고 그것으로 이동함. 레포가 늘었으면 빠진 것만 페인이 추가됨

### 이미 손으로 띄운 세션이 있으면

`grove open --exec` 은 빈 페인에만 에이전트를 띄움. 사람이 직접 `claude` 를 친
페인은 이름 없는 채로 남으므로, 그 페인에서 `/exit` 한 뒤 `--exec` 을 돌리라고
안내할 것. 확인은:

```bash
grove tell <작업명> --dry-run    # 누가 통지를 받는지 = 제대로 잡힌 세션 목록
```

## 하지 않을 것

- PLAN.md 를 임의로 갱신 — 어긋난 곳을 **보고만** 하고, 고칠지는 사용자가 정함
- 코드 수정 — 복귀는 파악까지임
- "이제 이렇게 하면 됩니다" 류의 해결책 제시 — 다음 한 수만 짚고 멈춤
